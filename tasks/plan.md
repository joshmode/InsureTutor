# Close remaining audit risks

User authorizes implementation of the outstanding engineering mitigations. Work in the existing checkout; preserve user data. Intrinsic natural-language uncertainty and unavailable external verification must remain explicitly bounded, not declared eliminated.

## Ordered slices and acceptance
1. **Grounding**: require per-claim evidence and fail-closed semantic review; reject retrieval-only irrelevant answers; deterministically disclose known source conflict. Tests for wrong-source/same-number, unsupported topic, injection, malformed reviewer and no-provider paths. Own files chat/orchestrator/prompts/guardrails/retrieval tests.
2. **Public API consumption**: bounded body (including chunked), per-client rate, shared durable global daily allowance, concurrency cap and provider-call budget; no untrusted forwarded-IP bypass; opaque errors and security headers. Test rejection before expensive work and release under errors/disconnect. Root owns middleware/config/api.
3. **Reproducibility**: hash-locked Python dependencies, pinned image digests, secure CA build option and native vulnerability checks. Build/check lock repeatability. Independent dependency files only.
4. **Corpus contract**: remove synthetic helpers and gate brochure-specific reconstruction by source fingerprint; invalidate stale indices and reject unsafe document paths. Provenance tests and changed-document regressions.
5. **Runtime responsiveness**: offload serialized retrieval from event loop; bounded resource work; measure health during concurrent chat. Load report from real app.
6. **Verification**: strict held-out evaluation separate from mechanical checks, optional live provider mode with exact prerequisites, actual hybrid model attempt, Chromium/Firefox/WebKit browser checks where available. No fabricated credentials, unsupported network bypass or unearned pass labels.
7. **Documentation/closure**: enumerate each old risk and evidence/disposition. Document API safeguards, privacy/storage limits, deployment boundaries and remaining external checks. Final review after tests/build/Docker/browser checks.

No new end-user account system or conversation database is needed for this public educational demo. Conversation state remains browser memory. Deployment safeguards must bound provider consumption for anonymous visitors. SQLite in the existing persistent data volume can coordinate local workers; multiple replicas on separate filesystems remain a documented deployment boundary.
