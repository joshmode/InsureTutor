## Deployment controls and defaults

The default is a bounded, single-service educational demo. All allowances reset on UTC calendar-day/minute boundaries; retaining `DATA_DIR` retains counters across restarts. Requests that reach admission consume chat allowance even if later invalid. Expiring concurrency leases recover after process failure. Provider reservations conservatively count failed calls and the full configured output ceiling, not an optimistic refund based on vendor usage metadata.

| Setting | Default |
| --- | --- |
| `MAX_REQUEST_BYTES` | 262144 actual bytes |
| `REQUEST_READ_TIMEOUT_SECONDS` | 10 |
| `CHAT_TIMEOUT_SECONDS` | 180 |
| `CHAT_REQUESTS_PER_MINUTE` | 20 per ASGI peer |
| `CHAT_REQUESTS_PER_DAY` | 500 globally |
| `CHAT_CONCURRENCY_LIMIT` | 4 globally on the shared volume |
| `PROVIDER_CALLS_PER_DAY` | 300 including review/repair |
| `PROVIDER_OUTPUT_TOKENS_PER_DAY` | 360000 reserved output tokens |
| `MAX_PROVIDER_INPUT_BYTES` | 64000 per call |
| `MAX_PROVIDER_RESPONSE_BYTES` | 262144 per reply/stream |

For a private funded demo, set **both** `APP_ACCESS_USERNAME` and `APP_ACCESS_PASSWORD` securely and use HTTPS remotely. The password is neither committed nor embedded in frontend JavaScript. Health is intentionally public and reveals readiness, model configuration status and corpus counts only. The container disables proxy-header trust by default; only enable it behind a specifically trusted gateway. Never trust arbitrary client `X-Forwarded-For` values, mount the Docker socket, grant privileged mode or add SYS_ADMIN. Terminate TLS at a maintained gateway and enforce edge-level connection/request limits. Multiple replicas on distinct filesystems must not each receive an independent copy of a supposedly global provider allowance.
